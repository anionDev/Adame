## Known issues and open findings

The following findings were identified during a code-review. They are not fixed yet because they require a bigger refactoring or a decision about the intended behavior.

### Testcases

- `test_command_create` and `test_command_stop` catch every exception and only write it to stderr without re-raising it. Therefore these testcases can never fail, independently of whether the assertions inside the `try`-block hold. Making them fail correctly will uncover currently hidden problems (for example the assertion that `FileMetadata.csv` is not empty, which does not hold because saving the file-metadata is disabled, see below).
- In `test_command_stop` and `test_command_create` the `EnvironmentForTest`-object is created inside the `try`-block while the `finally`-block accesses it. If the constructor throws an exception the `finally`-block fails with a `NameError` which hides the original exception.

### File-metadata and escaping of git-folders

- `__save_metadata` and `__restore_metadata` return immediately (with a comment explaining that escaping and restoring the permissions does not work properly). Consequences: `FileMetadata.csv` always stays empty and the permissions/owners of the files in the volumes are not restored when the repository is moved to another machine. This is one of the main features of Adame and should be repaired or removed entirely.
- `_internal_ensure_git_folder_are_deescaped` contains a `TODO` regarding the sorting of the entries: renaming an item inside an already renamed folder results in a `FileNotFoundError`.

### Intrusion-detection-system

- `__get_local_ip_address` returns the constant string `<insert local ip address>` instead of the real IP-address of the configured network-interface. This string is written into `Networktraffic.Generated.rules`.
- All rules generated by `__regenerate_networktrafficgeneratedrules_filecontent` (the `include` of the global snort-configuration and the test-rule) are commented out with a `TODO`. So the generated rule-file does not contain any active rule and snort is started with a file which effectively only contains the custom-rules.
- `__test_ids` is empty, so `__ensure_ids_is_running` does not verify that the IDS really works.
- The documentation (`Articles/Configuration.md`) documents `__localipaddress__` as placeholder while the implementation uses `__.builtin.localipaddress.__`. It has to be decided which of both is the intended placeholder.

### Container-handling

- `__run_system_command` always returns `true` (there is a corresponding `TODO`). Therefore `__start_container` logs "Container was started" even if starting the container failed.
- `_internal_container_is_running` and `_internal_ids_is_running` only read the last written state from `RunningInformation.txt` instead of really checking whether the processes are running (there is a corresponding `TODO`). After a reboot or a crash of the container the stored information is wrong.
- `_internal_remove_existing_container` is never called although `__start_container` contains the `TODO` "remove existing container if exist".

### Export of log-files

- If `logtargetfolder` is configured, `__exportlogs` moves all log-files to the target-folder (the source-files are deleted afterwards) before the export to the SIEM is executed. Therefore the SIEM does not receive any log-file as soon as `logtargetfolder` is set. It has to be decided whether both targets should be supported at the same time.

### Miscellaneous

- `checkintegrity` only writes a warning for each unsigned commit but always results in exitcode 0. So the command can not be used to detect integrity-violations in an automated way.
- `__check_integrity_of_repository` has the default-value `None` for the parameter `amount_of_days_of_history_to_check` which would result in a `TypeError` in `timedelta(days=None)`. Currently all callers pass a value.
- `__write_to_log` uses `datetime.utcnow()` which is deprecated and scheduled for removal in a future python-version.
- In `__create` the permissions of the IDS-log-folder are set to `666` recursively. Folders without the execute-bit can not be entered anymore, so this value is probably not the intended one for folders.
