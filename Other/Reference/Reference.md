# Adame

## Features

This section lists the typical features one can expect from Adame (as described in the `ReadMe.md` and the command-line-help). The `State` reflects whether the feature is actually functional in the current source-code (`available`) or whether it is documented/intended but not (fully) working yet (`unavailable`). Details for the limitations of the `unavailable`-features are collected in the `Findings`-section below.

| Id      | State       | Description                                                                                                                                                                              |
| ------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| feat-1  | available   | Create a new Adame-managed environment (a git-repository containing the configuration, the docker-compose-file, the IDS-rules and the volumes) via the `create`-command.                 |
| feat-2  | available   | Start the managed application-container (`start`-command, runs `docker compose up`).                                                                                                      |
| feat-3  | available   | Stop the managed application-container (`stop`-command, runs `docker compose down`).                                                                                                      |
| feat-4  | available   | Apply the current environment-configuration, including regenerating the IDS-rule-file (`applyconfiguration`-command).                                                                     |
| feat-5  | available   | Combined start which stops the container, re-applies the configuration, restores the state and starts the container again (`startadvanced`-command).                                     |
| feat-6  | available   | Combined stop which stops the container, commits the current state and exports the logs (`stopadvanced`-command).                                                                         |
| feat-7  | available   | Store every state-changing step of the environment as a commit in a git-repository, so the whole application including its data and configuration can be moved to another machine.        |
| feat-8  | available   | Back up the app-repository to a configured remote git-server (`git push` on each commit once a remote-address is configured).                                                            |
| feat-9  | available   | Sign commits with the owner's GPG-key to protect the integrity of the repository.                                                                                                        |
| feat-10 | available   | Check the repository-integrity by reporting commits which are not signed by the owner's GPG-key (`checkintegrity`-command).                                                              |
| feat-11 | available   | Automatically migrate an older repository-format-version to the current Adame-version when a command is executed.                                                                        |
| feat-12 | available   | Run a user-defined pre-script before starting the container and a post-script after stopping the container.                                                                              |
| feat-13 | available   | Integrate an intrusion-detection-system (snort) which is started and stopped together with the application (configurable via `enableids`).                                               |
| feat-14 | available   | Use user-defined custom IDS-rules (`Networktraffic.Custom.rules`).                                                                                                                        |
| feat-15 | available   | Export the collected log-files to a configured log-target-folder.                                                                                                                         |
| feat-16 | available   | Export the collected log-files to a SIEM-server via rsync/ssh.                                                                                                                            |
| feat-17 | available   | Diagnose the environment, e.g. check whether the required host-tools (docker, git, …) are available (`diagnosis`-command).                                                               |
| feat-18 | available   | Switch the environment to another git-branch/state (`checkout`-command).                                                                                                                  |
| feat-19 | unavailable | Automatically generated IDS-rules (the `include` of the global snort-configuration and the test-rule) — currently all generated rules are commented out (see SEC-2).                      |
| feat-20 | unavailable | Resolve the configured network-interface's real local IP-address for use in the IDS-rules — currently a constant placeholder is returned (see SEC-1).                                     |
| feat-21 | unavailable | Application-provided IDS-rules contributed through `ApplicationProvidedSecurityInformation.xml` — not implemented (see SEC-9).                                                            |
| feat-22 | unavailable | Self-test of the IDS which verifies that a configured test-rule actually triggers — not implemented (see SEC-3).                                                                          |
| feat-23 | unavailable | Capture the application-container-logs (`docker logs`) into the log-folder on stop — not implemented (see BUG-9).                                                                         |
| feat-24 | unavailable | Preserve and restore the file-metadata (permissions and owners) of the volumes when the repository is moved to another machine — currently disabled (see BUG-3).                         |
| feat-25 | unavailable | Reliably detect whether the container and the IDS are really running — currently only the last stored state is read, which becomes stale after a reboot or crash (see BUG-6).            |

## Findings

This section is the single place where findings of code-reviews, security-checks, bug-searches, performance-analyses and similar analyses of this repository are collected.
The handling of findings (id-form, prefixes, columns, state-determination, strike-through of fixed findings) is specified in `openspec/specs/common-projects-structure-architecture/spec.md`.

| Id        | Priority  | State | Description                                                                                                                                                                                                                                                                                                           | Impact                                                                                                                                                                                                         | Notes                                                                                                                                                 |
| --------- | --------- | ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| SEC-1     | high      | open  | `__get_local_ip_address` returns the constant string `<insert local ip address>` instead of the real IP-address of the configured network-interface; this string is written into `Networktraffic.Generated.rules`.                                                                                                    | IDS-rules that are meant to reference the local IP-address never match the real host, so this part of the network-traffic-detection does not work as intended.                                                 | `TODO calculate value` in `AdameCore.py.__get_local_ip_address`.                                                                                      |
| SEC-2     | high      | open  | All rules generated by `__regenerate_networktrafficgeneratedrules_filecontent` (the `include` of the global snort-configuration and the test-rule) are commented out with a `TODO`, so the generated rule-file contains no active rule and snort effectively runs only with the custom-rules.                         | The IDS starts without the intended generated ruleset, which reduces intrusion-detection to whatever custom-rules happen to exist.                                                                             | Found during code-review.                                                                                                                             |
| SEC-3     | mid       | open  | `__test_ids` is empty (`pass`), so `__ensure_ids_is_running` does not verify that the IDS really works.                                                                                                                                                                                                               | A non-functional IDS is reported as running, so intrusion-detection can be silently inactive.                                                                                                                  | `TODO Improve` in `AdameCore.py.__test_ids`.                                                                                                          |
| SEC-4     | mid       | open  | The documentation (`Articles/Configuration.md`) documents `__localipaddress__` as placeholder while the implementation uses `__.builtin.localipaddress.__`.                                                                                                                                                           | A custom IDS-rule written as documented uses a placeholder which is never substituted, so the rule does not receive the local IP-address.                                                                      | It has to be decided which of both is the intended placeholder.                                                                                       |
| SEC-5     | high      | open  | If `logtargetfolder` is configured, `__exportlogs` copies the log-files to the target-folder and deletes the sources before the SIEM-export runs, so the SIEM receives no log-file once `logtargetfolder` is set.                                                                                                     | Security-relevant log-files are not forwarded to the SIEM as soon as a log-target-folder is configured.                                                                                                        | It has to be decided whether both targets should be supported at the same time.                                                                       |
| SEC-6     | high      | open  | `checkintegrity` only writes a warning for each unsigned commit but the command always results in exitcode `0`.                                                                                                                                                                                                       | Integrity-violations (unsigned, potentially tampered commits) cannot be detected in an automated way because the command never fails.                                                                          | Found during code-review.                                                                                                                             |
| SEC-7     | high      | open  | In `__create` the permissions of the IDS-log-folder are set to `666` recursively.                                                                                                                                                                                                                                     | Folders lose the execute-bit and can not be entered anymore, and all contained files/folders become world-writable, which is both wrong for folders and a security-weakness.                                   | `666` is probably not the intended value for folders.                                                                                                 |
| SEC-8     | very high | open  | `__run_system_command` executes commands via `os.system(f"{program} {argument}")` (shell-execution) with interpolated, configuration-controlled values (for example the `networkinterface` and the application-name used to build the snort- and docker-commands).                                                    | A crafted configuration-value can inject arbitrary shell-commands which run with the elevated privileges Adame requires (command-injection).                                                                   | Found during the security-focused bug-search; non-trivial: requires a shell-less argument-array execution or strict escaping.                         |
| SEC-9     | mid       | open  | The application-provided security-information is never used: `__regenerate_networktrafficgeneratedrules_filecontent` sets `applicationprovidedrules = "# (not implemented yet)"` and the file `ApplicationProvidedSecurityInformation.xml` is created empty and never read.                                           | The documented mechanism by which an application contributes IDS-rules to improve its own security (`Articles/GeneratedFiles.md`) does not exist, so no application-provided rules are ever applied.           | `TODO Improve: Implement usage of application-provided security-information` in `AdameCore.py.__regenerate_networktrafficgeneratedrules_filecontent`. |
| SEC-10    | high      | open  | `__check_siem_is_reachable` returns `true` as soon as a SIEM-address is configured instead of really checking whether the SIEM is reachable (`TODO`).                                                                                                                                                                 | `__exportlogs` can delete local log-files after an rsync which it only assumes succeeded, and the "SIEM-connection missing"-warning of `applyconfiguration` is unreliable; security-relevant logs can be lost. | `TODO Improve` in `AdameCore.py.__check_siem_is_reachable`.                                                                                           |
| BUG-1     | mid       | open  | `test_command_create` and `test_command_stop` catch every exception and only write it to stderr without re-raising it, so these testcases can never fail regardless of whether their assertions hold.                                                                                                                 | Broken assertions stay hidden (for example the assertion that `FileMetadata.csv` is not empty, which does not hold because saving the file-metadata is disabled, see BUG-3).                                   | `test_command_start` already re-raises; `test_command_create` and `test_command_stop` do not.                                                         |
