# Adame

## Findings

This section is the single place where findings of code-reviews, security-checks, bug-searches, performance-analyses and similar analyses of this repository are collected.
The handling of findings (id-form, prefixes, columns, state-determination, strike-through of fixed findings) is specified in `openspec/specs/common-projects-structure-architecture/spec.md`.

| SEC-1     | open  | `__get_local_ip_address` returns the constant string `<insert local ip address>` instead of the real IP-address of the configured network-interface; this string is written into `Networktraffic.Generated.rules`.                                                                                                    | IDS-rules that are meant to reference the local IP-address never match the real host, so this part of the network-traffic-detection does not work as intended.                                                 | `TODO calculate value` in `AdameCore.py.__get_local_ip_address`.                                                                                      |
| SEC-2     | open  | All rules generated by `__regenerate_networktrafficgeneratedrules_filecontent` (the `include` of the global snort-configuration and the test-rule) are commented out with a `TODO`, so the generated rule-file contains no active rule and snort effectively runs only with the custom-rules.                         | The IDS starts without the intended generated ruleset, which reduces intrusion-detection to whatever custom-rules happen to exist.                                                                             | Found during code-review.                                                                                                                             |
| SEC-3     | open  | `__test_ids` is empty (`pass`), so `__ensure_ids_is_running` does not verify that the IDS really works.                                                                                                                                                                                                               | A non-functional IDS is reported as running, so intrusion-detection can be silently inactive.                                                                                                                  | `TODO Improve` in `AdameCore.py.__test_ids`.                                                                                                          |
| SEC-4     | open  | The documentation (`Articles/Configuration.md`) documents `__localipaddress__` as placeholder while the implementation uses `__.builtin.localipaddress.__`.                                                                                                                                                           | A custom IDS-rule written as documented uses a placeholder which is never substituted, so the rule does not receive the local IP-address.                                                                      | It has to be decided which of both is the intended placeholder.                                                                                       |
| SEC-5     | open  | If `logtargetfolder` is configured, `__exportlogs` copies the log-files to the target-folder and deletes the sources before the SIEM-export runs, so the SIEM receives no log-file once `logtargetfolder` is set.                                                                                                     | Security-relevant log-files are not forwarded to the SIEM as soon as a log-target-folder is configured.                                                                                                        | It has to be decided whether both targets should be supported at the same time.                                                                       |
| SEC-6     | open  | `checkintegrity` only writes a warning for each unsigned commit but the command always results in exitcode `0`.                                                                                                                                                                                                       | Integrity-violations (unsigned, potentially tampered commits) cannot be detected in an automated way because the command never fails.                                                                          | Found during code-review.                                                                                                                             |
| SEC-7     | open  | In `__create` the permissions of the IDS-log-folder are set to `666` recursively.                                                                                                                                                                                                                                     | Folders lose the execute-bit and can not be entered anymore, and all contained files/folders become world-writable, which is both wrong for folders and a security-weakness.                                   | `666` is probably not the intended value for folders.                                                                                                 |
| SEC-8     | open  | `__run_system_command` executes commands via `os.system(f"{program} {argument}")` (shell-execution) with interpolated, configuration-controlled values (for example the `networkinterface` and the application-name used to build the snort- and docker-commands).                                                    | A crafted configuration-value can inject arbitrary shell-commands which run with the elevated privileges Adame requires (command-injection).                                                                   | Found during the security-focused bug-search; non-trivial: requires a shell-less argument-array execution or strict escaping.                         |
| SEC-9     | open  | The application-provided security-information is never used: `__regenerate_networktrafficgeneratedrules_filecontent` sets `applicationprovidedrules = "# (not implemented yet)"` and the file `ApplicationProvidedSecurityInformation.xml` is created empty and never read.                                           | The documented mechanism by which an application contributes IDS-rules to improve its own security (`Articles/GeneratedFiles.md`) does not exist, so no application-provided rules are ever applied.           | `TODO Improve: Implement usage of application-provided security-information` in `AdameCore.py.__regenerate_networktrafficgeneratedrules_filecontent`. |
| SEC-10    | open  | `__check_siem_is_reachable` returns `true` as soon as a SIEM-address is configured instead of really checking whether the SIEM is reachable (`TODO`).                                                                                                                                                                 | `__exportlogs` can delete local log-files after an rsync which it only assumes succeeded, and the "SIEM-connection missing"-warning of `applyconfiguration` is unreliable; security-relevant logs can be lost. | `TODO Improve` in `AdameCore.py.__check_siem_is_reachable`.                                                                                           |
| BUG-1     | open  | `test_command_create` and `test_command_stop` catch every exception and only write it to stderr without re-raising it, so these testcases can never fail regardless of whether their assertions hold.                                                                                                                 | Broken assertions stay hidden (for example the assertion that `FileMetadata.csv` is not empty, which does not hold because saving the file-metadata is disabled, see BUG-3).                                   | `test_command_start` already re-raises; `test_command_create` and `test_command_stop` do not.                                                         |
| BUG-2     | open  | In `test_command_create` and `test_command_stop` the `EnvironmentForTest`-object is created inside the `try`-block while the `finally`-block accesses it.                                                                                                                                                             | If the constructor throws an exception the `finally`-block fails with a `NameError` which hides the original exception.                                                                                        | Found during code-review.                                                                                                                             |
| BUG-3     | open  | `__save_metadata` and `__restore_metadata` return immediately, so `FileMetadata.csv` always stays empty and the permissions/owners of the files in the volumes are not restored when the repository is moved to another machine.                                                                                      | One of the main features of Adame (preserving file-metadata across machines) does not work.                                                                                                                    | Disabled because escaping and permission-restoring do not work properly; should be repaired or removed entirely.                                      |
